# 11/17 회의 화면 개선

기준: `origin/main` `d3680b5`, 브랜치 `feature/meeting-1117-ui`. 결정 내용은 회의록과 `네비-AI-통일` 목업을 따른다.

## 작업일지

- 운영·캘린더에서 글자 앞 아이콘, 카테고리 색상, 행 구분선을 없앴다. 캘린더 날짜 아래에는 단색 점만 두고 종류는 글자로 쓴다.
- 다크 모드 카드는 모서리 14pt, 카드 `#1A1A1D`, 배경 `#101012`로 바꿨다. iOS `List`의 기본 모서리는 바꿀 수 없어 `CardSection`이 행 배경을 직접 그린다.
- 예약·문의·업무 상세를 `AppRoute` 하나로 모아 어느 탭에서 열어도 같은 화면을 쓴다.
- 체크한 수업과 할 일은 취소선을 그은 채 목록에 남는다.
- 예약금, 주문 확인, 포장, 송장, 배송 완료, 할 일은 상세에서 한 단계씩 되돌린다.
- 운영 현황 기간은 달력에서 시작일과 종료일을 고르고, 서버가 그 기간으로 다시 계산한다.
- 운영 현황의 숫자 4개는 처리율 링 오른쪽의 남은 폭을 2열로 나눠 채운다. 웹은 이미 같은 배치다.
- 문의, 홍보 글, 추천은 같은 비서 초안 카드를 쓴다. 승인·반려를 반복할 수 없고, 되돌리기로 검토 대기로 돌아간다.
- 예약 전체보기는 날짜별 목록이다. 휴대폰 폭에서는 네 항목이 한 줄에 들어가지 않아 예약자를 클래스 아래에 둔다.
- 웹은 720px 이상에서 창 전체를 쓰고, 예약 상세는 왼쪽 정보, 오른쪽 처리의 2열이다.

## 11/19 디자인 수정안 반영 (B안)

- 캘린더의 주황 점과 "확인 필요"는 같은 날 "모노 타임라인" A안으로 대체했다(아래).
- 운영 현황: 콘텐츠 대신 문의를 보여 줘 네 숫자의 합이 처리율 분모와 같다. "N건 중 M건 처리"와 숫자별 보조 설명을 넣고, 전월 대비 줄은 뺐다. 기간 버튼은 한 달이면 "11월", 직접 고르면 날짜 범위다.
- 먼저 확인해주세요 행에 보조 설명을 넣었다. 아이콘은 넣지 않았다.
- 전체 업무 관리와 기회 행에만 단색 아이콘을 넣었다.
- 주문·배송 상세: 판매 채널, 진행 단계(결제 → 주문 확인 → 포장 → 발송 → 배송 완료), 라벨-값 정보, 본문 끝 처리 버튼과 그 자리의 되돌리기.
- 넣지 않은 것: 고객 메시지 보내기(발송 기능 없음), 배송지·요청사항(DB에 없음), 남은 N건 보기(통합 목록 화면 없음), 하단 고정 버튼(탭 바와 비서 막대가 겹침). 웹도 아직 바꾸지 않았다.
- QA: Server 237개, Core 13개, UI 테스트 20개 통과. 스크린샷 투어는 업무 관리 행이 첫 화면 아래로 밀려 기간 버튼을 기다리도록 고친 뒤 다시 통과했다. 시뮬레이터 직접 확인: 라이트·다크 운영 현황, 직접 고른 기간, 주간·월간 주황 점, 일정 묶음과 지금 선, 주문 확인과 되돌리기.

## 11/19 캘린더 A안 "모노 타임라인"

- 색 없이 모양·굵기·명도로만 구분한다. 색은 `CalendarTokens` 7개뿐이고 포인트는 라벨 색 하나다.
- 구조: 자체 머리말(제목, "오늘 일정 N건", +), 주간/월간 세그먼트, 기간 이동 줄(기간, 오늘, ‹ ›), 주간 7칸 또는 월간 그리드, 날짜 머리말, 고정 상자(종일·새 주문), 타임라인, 범례.
- 점은 일정 양(1~2건 1개, 3~5건 2개, 6건 이상 3개). 노드 모양은 종류, 상태는 굵기와 명도. 다음 일정은 소요 시간에 비례한 바와 "N분 후 시작"을 붙인다.
- 할 일 노드를 누르면 기존 완료 API로 토글한다. 그날 주문은 새 화면 `DayOrdersView`로 연다.
- 서버: 일정 응답에 `minutes`, `subject`(첫 예약자와 인원, 공급처), `amountWon`, 할 일 `revision`을 추가하고 B안의 `needsAction`은 지웠다. 저장 필드와 마이그레이션은 바꾸지 않았다.
- 시스템 달력(`MonthCalendarView`)과 예전 일정 행(`AgendaRow`)은 지웠다.
- 문서와 다르게 한 것: 날짜 영역은 Dynamic Type xxxLarge에서 멈춘다(7칸 고정 폭이라 AX5에서 화면이 옆으로 넘쳤다). 큰 글씨에서는 시간을 제목 위로 옮긴다. 할 일 노드는 행과 별개의 접근성 버튼이다. 디버그 빌드에서 `ROUNDUP_CALENDAR_NOW`로 현재 시각을 고정할 수 있다.
- QA: Server 237개, UI 테스트 20개 통과(스크린샷 투어는 새 세그먼트를 기다리도록 고친 뒤 다시 통과). 시뮬레이터 직접 확인: 주간 라이트·다크, 월간, 빈 날짜, AX5, 13:30 고정 시각의 다음 일정·현재 시각 선, 할 일 완료 토글.

## 11/20 2차 디자인 수정 (11개 항목)

- 캘린더 1·2: 직접 그린 머리말을 없애고 시스템 큰 제목·부제·툴바 + 버튼을 쓴다. 다른 탭과 제목 높이가 같고 스크롤하면 작은 제목이 생긴다.
- 캘린더 3·4: 다음 일정 문구를 표대로 바꾸고(2시간 넘으면 "오전 9:00 시작"), 다음 일정 노드는 16pt, 바는 소요 시간이 없어도 24pt로 항상 붙인다. 행 최소 높이 96.
- 캘린더 5: 시간이 지난 미완료 할 일은 `missed`(빨간 점선 원, "지남", "오늘로 옮기기"). 옮기면 시각은 유지하고 이미 지났으면 오늘 23:59로 둔다. 되돌리기 알림을 6초 보여 준다. 서버에 `POST /tasks/{id}/move`, `POST /calendar/events/{id}/move`를 추가했다.
- 캘린더 6: 시간 일정이 없는 날은 시계 아이콘과 "시간이 정해진 일정이 없어요"(고정 상자도 없으면 "일정이 없어요"), 범례 숨김.
- 7: 기한은 서버가 시각(`due`)으로 보내고 앱의 `RelativeDayFormatter`가 오늘/어제/N일 뒤/날짜를 만든다. 시드의 "오늘이 결과 발표일이에요."는 "키링 이벤트 결과 발표"로 바꿨다. 날짜가 바뀌면 앱이 데이터를 다시 불러온다.
- 8: `overdueRed`(라이트 #C62828, 다크 #FF6B60)는 "기한 지남"과 시계, 놓친 할 일 노드에만 쓴다. 기한 지난 항목은 목록 맨 위로 올린다. 기한 전 시계는 회색이다.
- 9: 발송 집계를 `metrics.to_send` 하나로 묶어 오늘 탭 "오늘 발송", 운영 "발송 대기"와 배지, 캘린더 오늘(수거 예정 + 못 보낸 택배 고정 행)이 같은 수를 낸다.
- 10: 운영·설정 메뉴 아이콘을 `MenuIcon`(22pt, regular, 단색, 28pt 열)으로 통일하고 예약 관리 아이콘을 `calendar`로 바꿨다.
- 11: 오늘 탭 큰 제목을 `TodayHeadline`(RoundupCore 순수 함수) 규칙으로 바꾸고 규칙별 단위 테스트 7개를 붙였다. 서버는 `/today`의 `headline`으로 재료 숫자만 보낸다.
- 문서와 다르게 한 것: 할 일·직접 추가한 일정은 DB에 "시각 없음"이 없어, 옮길 때 오늘 시각이 이미 지났으면 종일 대신 오늘 23:59로 둔다. 문의에는 기한이 없어 제목 1번 규칙은 택배와 할 일만 본다. 예약 도착 예정·운영 첫 예약금 대기자 같은 나머지 상대 날짜 문구는 서버가 요청 때 만들고, 날짜가 바뀌면 다시 불러와 맞춘다. 6번 21시 조건은 문서 순서대로 4·5번이 먼저 걸린다. 오늘 탭과 캘린더는 `TimelineView(.everyMinute)` 대신 1분 타이머로 `now`를 갱신한다. 시스템 큰 제목이 접힐 때 TimelineView로 감싼 목록이 다시 그리기를 끝없이 반복해 앱이 멈췄기 때문이다(UI 테스트 중 CPU 100%로 확인).
- 오늘 탭 제목을 `TimelineView`로 감쌓더니 목록을 끝까지 스크롤할 때 레이아웃이 멈추지 않고 돌아 앱이 멈췄다(CPU 100%, UI 테스트 1개 시간 초과). 1분 타이머로 `now`만 갱신하도록 바꿔 해결했다.
- QA: Server 241개, Core 20개, UI 테스트 20개 통과(탭 제목 테스트는 바뀐 오늘 제목에 맞게 고친 뒤 다시 통과). 시뮬레이터 직접 확인: 오늘 탭 제목("답변 기다리는 문의 3건" → 택배 기한을 어제로 바꾼 뒤 "못 보낸 택배 1건"), 오늘 탭·운영·SNS 관리의 기한 지남 행, 캘린더 오늘·스크롤·지난날·빈 날·다크, 오늘로 옮기기와 되돌리기.

## 서버 변경과 배포 조건

- 기존 필드와 API는 유지하고 상세, 되돌리기, 비서 초안, 기간 조회 API를 추가했다.
- 마이그레이션 `0003`이 홍보 글과 추천에 `rejected` 상태를 허용한다. 배포 스크립트가 실행할 때 운영 DB에 적용된다.
- 새 앱의 상세 화면과 되돌리기는 이 서버가 배포되어야 운영 환경에서 동작한다. 앱과 서버는 함께 합치거나 서버를 먼저 합친다.
- 되돌리기 허용 판단은 서버 `common.can_reopen`과 Core `Inquiry.canReopen`에 있다. 실제 발송이나 게시를 만들면 이 지점에서 막는다.
